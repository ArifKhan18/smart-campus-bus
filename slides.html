Problem Statement

03

Traditional university transport systems suffer from structural inefficiencies that affect students, drivers, and administration.

❌ Student Challenges

  • 1. Blind Waiting: No real-time ETA or bus location details
  • 2. Schedule Chaos: Paper-based schedules change without notifications
  • 3. Isolation: No instant passenger-driver communication channel

❌ Driver & Admin Bottlenecks

  • 4. Driver Distraction: Managing notifications manually while driving
  • 5. Zero Visibility: Admins cannot track bus status or route speeds
  • 6. Report Delay: Student safety/issue complaints take days to process

Project Objectives & Goals

04

Our primary goal is to build an automated, real-time bus tracking and communication system tailored for campus transit.

🎯 Primary Objectives

  • ✓ Develop high-accuracy GPS tracking with 5s updates
  • ✓ Integrate Haversine engine for precise stop-wise distance & ETA
  • ✓ Provide real-time communication grouped by active buses
  • ✓ Establish dynamic administration fleet management

📈 Key Target Benefits

  • ⚡ Reduce student waiting times at campus stops
  • ⚡ Replace manual notices with automatic push alerts
  • ⚡ Facilitate immediate response to breakdown reports
  • ⚡ Generate fleet analytics to optimize transit scheduling

Proposed Solution — SmartBus

05

A secure, multi-role web platform linking students, drivers, and admins in a single real-time ecosystem.

📱 Student Portal

Live Leaflet mapping, distance/ETA tracker, bus chatroom, campus notices, admin reporting dashboard.

👨‍✈️ Driver Dashboard

Single-tap trip setup, automatic Geolocation tracking broadcaster, instant delay alerts, Bangla UI.

💼 Admin Control Panel

Interactive route mapping, bus/driver matching, user blocking, broadcast notice publisher, real-time analytics graphs.

Development Methodology & Workflow

07

Our development followed an iterative agile model, focusing on real-time data sync and security at every phase.

📋 Phase 1: Planning & Database Design

Defined User, Bus, Route, and Notice models. Configured Firebase Firestore indexes for quick querying.

🎨 Phase 2: Responsive Prototyping

Built standard dark and light interfaces for mobile, tablet, and desktop screens.

🔧 Phase 3: REST API & Auth Engine

Implemented JWT Bearer tokens and safe OTP authentication via Brevo SMTP API.

🗺️ Phase 4: GPS Location Broadcast Engine

Integrated HTML5 Geolocation API with Leaflet mapping and dynamic coordinate pan.

💬 Phase 5: Real-time Communication Integration

Implemented Firestore snapshots for live bus-wise community group chats.

🧪 Phase 6: Testing & Cloud Deployment

Conducted xUnit backend tests and Playwright frontend E2E tests before cloud deployment.

What Makes SmartBus Different

17

🧮 Haversine Formula ETA

Calculates geographical distance and arrival times using GPS coordinates — not straight-line guesses.

💬 Bus-Wise Group Chat

Firebase-powered real-time chat grouped by active bus for immediate passenger communications.

🌐 Full Bilingual UI

Complete interface localization. Driver trip console works in both English & বাংলা.

📊 Fleet Analytics & Builder

Dynamic Leaflet map coordinates builder combined with Chart.js analytics for administrative control.

Conclusion & Future Scope

18

SmartBus bridges the gap between campus transport and real-time connectivity, making commutes safer and more predictable.

🏁 Summary Conclusion

- Successfully developed a robust real-time tracking application for campus fleet transit.

- Successfully integrated NoSQL Firestore and C# REST services for multi-role security and data synchronization.

- Validated features through rigorous xUnit unit tests and Playwright E2E testing pipelines.
